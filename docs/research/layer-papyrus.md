# The essentials layer under the Papyrus event block

Generated by chim/.scratch/layer_papyrus.py from a persist-mods dry run of the layer at f8f92ea4: every Papyrus script the clients receive, loose (`scripts/*.pex`) or inside a BSA, with the parent class read from the compiled file header (nothing decompiled). Names only; what a script does is not read here.

**The block (numidium, x-survival-why 20261020-020729; thuum-magnus on FridaHooks.cpp 28-152):** in a connected game skymp5-client sets Skyrim Platform's Papyrus event block at its first tick (blockPapyrusEventsService.ts). From then on OnUpdate is dropped for every script; every other event is dropped for a script not named `SKI_*`, `RaceMenu*`, `GRIM_ALT_TeleportationMarker`, `WB_DestroyAfterDelay_Script` or `defaultDisableHavokOnLoad`; only ActiveMagicEffect events on the player are spared. Measured: SurvivalModeMainQuest runs but its 5 s RegisterForSingleUpdate never fires, so Survival cannot start connected; the same block hides every MCM (SkyUI's own SKI_ scripts run, the mods' config scripts never register). Solo runs have no skymp5-client and are untouched.

**Reading the verdicts.** `blocked`: the mod's own event scripts (Quest, ReferenceAlias, ObjectReference, Actor, Perk, MCM bases, ...) are outside the whitelist, so whatever those scripts do is inert connected; the mod's records, DLLs and assets still work. `effects only`: every script is an ActiveMagicEffect, so it works on the player and not on other actors, and any OnUpdate loop in it is dead. `mixed`: both kinds. `whitelisted`: every script is admitted by name. `libraries`: scripts whose parent is no event host (function libraries, fragments of non-event parents). `no scripts`: nothing to block. A mod tagged **fixes vanilla scripts** ships fixed copies of the game's own scripts, which a connected game does not run either (the server owns quests and dialogue), so the block changes nothing for it.
