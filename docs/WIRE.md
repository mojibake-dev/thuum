# WIRE: the network edge in Rust

Why this exists: ADR-010. What it is: one Rust workspace, `skymp/skymp-wire/`
inside the fork (ADR-015), that owns every byte that arrives from the
network, on the server and in the client, and hands the rest of the system
decoded, bounded, validated structs. The C++ core stops parsing network input
the day the bridge lands. M0 built the crates; M1 ports SkyMP's own
protocol onto them (ADR-019, section "The M1 port" below).
Everything below is the spec for M0.

## Crates

```
skymp/skymp-wire/
  crates/
    wire-schema       message types; serde + postcard; heapless bounds; ids append-only
    wire-codec        encode/decode with per-message size caps; the only bytes-to-struct path
    wire-validate     structural validation: ranges, rates, owner shape, reason codes
    wire-transport    renet + renet_netcode server and client; channel map; token issuer
    wire-bridge       cxx bridge into the C++ server (unsafe allowed, reviewed)
    wire-client-ffi   cdylib loaded by the Skyrim Platform client; committed C header
  difftest/           replays recorded sessions into C++ core and Rust edge, diffs outputs
  fuzz/               cargo-fuzz targets: codec_decode, validate, transport_ingest
```

Dependency direction is strictly downward: schema <- codec <- validate <-
transport <- bridge / client-ffi. Only `wire-transport` names renet types, so
the transport can be swapped for quinn (ADR-011) without touching anything
above it.

Pins (ADR-015): heapless 0.7 with `serde`, postcard 1.1 with `heapless` and
`experimental-derive` (its `MaxSize` derive over heapless types needs exactly
this pair), renet 2 with the renet_netcode release that pairs with it,
rust-version 1.88 for cxx. cbindgen is not a dependency: it is a CLI run by
`just wire-header`, the header it generates is committed at
`crates/wire-client-ffi/include/skymp_wire.h`, and `just wire-header-check`
in CI diffs a fresh generation against the committed file.

## The M1 port (ADR-019)

SkyMP already split format from transport: 33 message types, each with one
field list (`Serialize(Archive&)`) that drives a binary encoding on the wire
and a JSON form for JavaScript. The port keeps the JSON form as the
in-process contract and replaces everything between the two processes'
JSON with Rust.

```
skymp5-client (TS)  JSON  MpClientPlugin.dll (Rust)  postcard/renet  wire-bridge (Rust)  JSON  C++ core
                          wire-client-ffi                            WireServer.cpp (an IServer)
```

- wire-schema holds the 33 messages as structs with the C++ field lists
  and JSON keys (wire id = MsgType + 8), collections as bounded heap types,
  a byte cap per message (`Message::max_len`, checked from the variant tag
  before the body is read). thuum's own messages continue SkyMP's numbering
  after 33, in the same family and the same JSON form, and the C++ core and
  skymp5-client gain the type alongside: 34 SetGameTime, the server's game
  clock (docs/verbs/time.md; SCHEMA_VERSION 3, reason E_VAL_RANGE, code
  207).
- wire-json renders a decoded, validated message as exactly what
  JsonOutputArchive writes (absent optionals omitted, `"t"` included,
  nested `"t"` quirks kept) and recognizes JSON from the core or the client,
  dispatching on `"t"`. Its fixtures (two per type) are the shared contract:
  `cargo test -p wire-json` renders them back unchanged, and the fork's T0
  test `unit/WireJsonContractTest.cpp` reads each through the core's
  ReadJson and WriteJson and must do the same.
- Client: the wire-client-ffi cdylib is MpClientPlugin.dll with SkyMP's
  seven C exports (CreateClient, DestroyClient, IsConnected, Tick, Send,
  SendRaw, MpCommonGetVersion), the header in include/skymp_wire.h matching
  the old ABI. It runs the transport on a thread of its own: netcode drops a
  connection silent for 15 s and Skyrim's main thread, which calls Tick,
  stalls through loading screens (RakNet had its own thread too). Inbound
  messages wait in a bounded inbox as JSON; a game that stops reading long
  enough to fill it is disconnected rather than desynchronized.
- Server: addon/WireServer.cpp implements `Networking::IServer` over
  wire-bridge: inbound messages reach PacketParser as `0x86 + JSON`, the
  input MessageSerializer's JSON path already read, and the core's sends
  (MessageSerializer now writes `0x86 + JSON`) go back to Rust, which
  recognizes, direction-checks, validates and encodes them, reusing the last
  encoding while a broadcast repeats it. The six relays (SendToNeighbours)
  forward Rust-rendered JSON. User ids map to transport clients as IdManager
  mapped RakNet guids; the guid the TypeScript login reads is `wire-<id>`.
- Build: cmake/wire.cmake imports the workspace through corrosion; the
  bridge's cxx glue is generated by cxxbridge and compiled by the server's
  own compiler (corrosion_add_cxxbridge), so wire-bridge has no build
  script. The server image installs Rust; the Rust fakeclient lands in
  dist/server/fakeclient, where the ctest integration test
  misc/tests/test_fakeclient_smoke.js runs it against the server.
- Deleted with the port: RakNet (SLikeNet and its overlay port), the
  BitStream archives, MessageSerializer's binary paths, IdManager, the C++
  MpClientPlugin and fakeclient, their unit tests.

Measured on the green two-client capture (run 20261001-233455, 92 distinct
packets of 11 types, decoded by wire-legacy into the schema): every packet
fits the capacities. postcard spends a byte where the BitStream spent a bit
(bools, optional presence), so the hot path shrinks and option-heavy
messages grow:

| MsgType | packets | legacy bytes | postcard bytes |
| --- | --- | --- | --- |
| 2 UpdateMovement | 24 | 1416 | 1296 |
| 5 UpdateEquipment | 12 | 2824 | 3084 |
| 28 SetInventory | 1 | 203 | 314 |
| 33 CreateActor | 40 | 5412 | 5786 |

Found on the way: the old binary reader trusts its 32-bit length prefixes
(BitStreamInputArchive: "TODO: check n before resizing"), so one crafted
packet makes a server, or a malicious server makes a client, append up to
2^32 elements; and serde_json parses floats approximately unless its
`float_roundtrip` feature is on (fuzz/validate caught an f64 snippet
argument coming back one digit off; JavaScript and simdjson round
correctly).

## Transport (ADR-011)

renet channels, configured in `wire-transport::channels`:

| Channel | renet SendType | Carries |
| --- | --- | --- |
| 0 `ReliableOrdered` | ReliableOrdered | every send its sender marks reliable |
| 1 `ReliableUnordered` | ReliableUnordered | the default of the reserved M0 families only (Hit, ReservedHostedActor, InventoryApply), which no sender uses today |
| 2 `Unreliable` | Unreliable | every send marked unreliable (movement, animation, a client's ChangeValues) |

A reliable send is resent by renet until acked only while renet's
connection clock advances; until fork branch wire-renet-clock (2026-10-21,
docs/research/transport-clock.md) the transport's polls never called
`RenetServer::update` or `RenetClient::update`, so the clock stood at zero
and a lost reliable packet was never resent; the fix calls both before the
transport's update, renet's own order.

Outbound packets leave on a flush clock, not at every poll (D64, 17:26 PDT 2026-10-29;
fork m3-send-rate): the gamemode polls the server about 800 times a second (a
tick, then a 1 ms sleep, skymp5-server/ts/index.ts), and renet sends a packet to
every connection at each `send_packets`, so a flush per poll cost an idle
client 814.8 packets a second of 26 to 31 B (x-wire-idle-rate on sky-srv,
numidium: equal to the 816.4 ticks a second within 0.2 percent, near 45 KB/s a
seat with headers). `wire-transport::FlushClock` accumulates the polled time and
flushes at `Options::send_interval` (`SEND_INTERVAL_DEFAULT` 1/60 s; zero is
the old shape), keeps the remainder so the long-run rate is the interval's,
never bursts after a stalled tick, and a disconnect flushes at the next poll.
Ingest, validation and the game's tick keep their cadence; a message queued
between flushes waits at most 16.7 ms. The clients flush at their own poll (a
frame on a seat, 5 ms on the fakeclient); their rate is theirs. Measured 18:43 PDT 2026-10-29 on the
branch's image: 59.98 packets a second to the idle client (all 26 B, a median gap of
16.6 ms) with the loop still at 847 ticks a second, T2 green.

SkyMP's senders choose per send (`reliable` true or false), and
`wire-transport::channels::for_send` maps that choice: reliable to channel 0,
unreliable to channel 2 (SkyMP's server sent reliable as RELIABLE_ORDERED and
its client as RELIABLE; ordered only adds ordering, ADR-019). Channel 1 is
the per-family default for the M0 messages, which have no JSON form and are
never sent; the table this section once gave (effects, container deltas and
hits on channel 1) was the plan, not the code, as the architecture diagram's
survey found (docs/architecture/thuum-system.drawio, 2026-10-10). One
consequence: messages a sender marks reliable keep their order relative to
each other, which magic-effects relies on (MagicEffects before the
ChangeValues of the same change).

Authentication: netcode connect tokens. The lab runs `Unsecure`. A public
server runs `Secure` with a private key held by the server process and a
tiny issuer endpoint (`wire-transport::token`): password or invite in,
signed token out, over HTTPS terminated by the operator's proxy. The token
carries per-connection keys, so encryption and replay protection come with
the transport and are not something a handler can forget.

Limits live in `wire-transport::limits` and are enforced before decode:
max clients (netcode), max reassembled message size, bytes per second per
client, channel memory as the queue depth (renet disconnects a client whose
reliable channel fills), and messages per second per family (the validator's
token buckets). Not enforced in the crate: a connect-rate cap per source
address. The netcode transport owns the socket, so nothing above it sees a
handshake before it is processed; that cap lives at the host firewall until
the transport grows a hook for it, and this sentence is the record of the gap.

## Messages (ADR-012)

`wire-schema` defines one `enum Message` with a `u16` id per variant. Ids
are append-only. Each variant is a struct whose fields are scalars or
`heapless::Vec<T, N>` / `heapless::String<N>` with capacities named as
constants next to the type and chosen from the game (inventory delta count,
effect list length, name length). `postcard` encodes; decode of an
over-capacity collection is an error at the exact field, never a truncation.

Decode is canonical as well as total. postcard accepts overlong varint
encodings on input, so two byte strings can decode to one message; the codec
re-encodes what it decoded and compares, rejecting a mismatch with
`E_WIRE_NONCANONICAL`. A message therefore has exactly one byte
representation on the wire, which is what lets `codec_decode` assert a
byte-identical round trip and what keeps the recognizer's input language no
larger than the messages need.

Families, mirroring the authority rungs:

- Session: hello, version, mod list hash, disconnect reason. Live since
  mod-lock (docs/verbs/mod-lock.md, fork m3-mod-lock): Hello (id 0, C2S)
  carries one hash per plugin, the full plugins in the engine's load order
  then the light ones, each FNV-1a 64 over lowercase(name) + 0x00 + size as
  u32 LE + crc32 as u32 LE (wire-rules mods.rs, the one definition; the
  client's src/lib/modHash.ts pinned to the same vectors); the bridge judges
  it against the server's manifest.json and answers Welcome (id 1) or Refuse
  (id 2) with a reason code: 501 E_MOD_LOCK_COUNT, 502 E_MOD_LOCK_MISMATCH,
  503 E_MOD_LOCK_NO_HELLO (a login before any Hello, when the server
  requires one); the refused connection is dropped on the next poll. The
  session family has no SkyMP MsgType: between a plugin and its wire DLL it
  travels as JSON keyed by "w" (0, 1, 2), hashes as 16 lowercase hex digits,
  the DLL filling schema_version when the plugin omits it.
- Ownership: cell host grant, host handoff, host release (R0 decisions):
  HostGrant (id 56, MsgType 48) and HostRelease (id 57, MsgType 49) with the
  cell and its epoch, fed by the client's CellLoaded (id 55, MsgType 47, an
  Intent: a cell fully loaded or gone from the loaded set), docs/verbs/
  cell-host.md; the M0 rows 7 and 8 stay reserved and dead
  (ReservedHostGrant, ReservedHostRelease); the handoff is npc-handoff's.
- Intent: movement sample, animation event, cast intent, hit intent,
  activate intent, aim pitch (R1 inputs; the validator's main customers);
  a host's checked death report for a game-file actor (ActorDeath 52,
  npc-fate, M3).
- Record: NPC state under host, physics owner updates (R2 inputs): a host's
  state for an actor it simulates (HostedActorState, id 61, MsgType 53,
  npc-stream, M3: the three percentages bounded by the server's numbers, the
  combat target and the package recorded) and a spoken line beginning on
  such an actor (ActorSpeech, id 62, MsgType 54, the voice slice); the M0
  row 5 stays reserved and dead (ReservedHostedActor, renamed 2026-10-26).
- World: server-decided deltas broadcast to renderers (R0 outputs); the
  server's roll of a placement ahead of the engine's own (ActorFate 51,
  npc-fate, M3).
- Snippet: delegated Papyrus execution request and result (R2, ledgered).

Every message documents: direction, rung, idempotency, and the reason codes
its validator can emit. Replay protection follows the channel: Movement
rides Unreliable with "later sample wins", so its check is monotonic on
`seq`; Hit rides ReliableUnordered, where reordering is legal and a
monotonic check would drop legal hits, so the validator keeps a sliding
window bitmap of recently seen `seq` values per client and rejects only a
repeat inside the window. Schema export (`just wire-schema`) writes a JSON
description consumed by the napi layer for the TypeScript gamemode and by
docs; C++ never sees bytes, only structs across the bridge.

### CreateActor's props for an observer (figure-values, train-28)

CreateActor's optional props `health`, `magicka` and `stamina` travel to an
observer too, once the actor's player has an actor-values record: they are
the player's recorded maxima (bases 24, 25, 26 with the running buffs),
which the other game sets as its figure's base values instead of the million
the client used to set (thuum docs/verbs/figure-values.md). A change of the
record or of a buff that moves a maximum follows as three UpdateProperty
messages (t 7) named `health`, `magicka` and `stamina`, to every game that
sees the actor. The owner's own CreateActor carries the race's bases and the
percentages as before. No field is new, so the validator is unchanged: the
props were optional finite floats already.

### CreateActor's refr_id and base_record_type for an actor from the game files (npc-puppet, M3)

An actor the server loads from the game files (a Skyrim.esm ACHR such as
the forest predator 0x85547) travels in CreateActor (t 33) under its own
form id, and its `baseRecordType` carries `NPC_` (DOOR was the only value
before). Upstream sent id + 0x100000000 so the client would place a copy of
the base; the client now binds the engine's own reference and runs it or
puppets it by the server's word (thuum docs/verbs/npc-puppet.md, ADR-045
point 2 as revised 2026-10-22). The property `isHostedByOther` is carried
explicitly, true or false, in every actor's CreateActor (a player's figure
always true; any other actor true unless the listener hosts its cell), and
UpdateProperty (t 7) flips it under the actor's own id at every grant and
release, game-file actors included (the first cut withheld it from them:
under upstream's id + 0x100000000 the flip under the raw id never reached
the copy, playtest thirty's wolves; with the engine's reference bound to a
view it does). Values within the existing types, no shape change, no
validator change.

### ActorSightings (t 50): a host's roster of game-file actors the server does not hold (npc-puppet, M3)

Client to server, reliable, R1. Every 2 s while any remain, a game that hosts
at least one cell sends the game-file actors its engine has attached that it
holds no form model for: `sightings`, at most 64 of `{ refrId: u32 (under
0xff000000), worldOrCell: u32 (the worldspace, or the interior cell), pos:
[f32; 3], rot: [f32; 3] }` (skymp5-client HostService.reportSightings). The
reason (thuum docs/verbs/npc-puppet.md, ADR-045's revision of 2026-10-22): the
server loads a placed actor by its placement square, and a village's named
residents are placed in their houses and walked outside by their schedules,
so their host's engine has them where the server has nothing (b-npc-puppet
20261022-081631 and 090227; x-npc-sigrid-ref 091354 read Sigrid 0x13483 in
RiverwoodAlvorsHouse 0x133c8). The server (PartOne::OnActorSighting) takes an
entry only when the sender hosts the cell of the sighted position
(WorldState::CellOf of worldOrCell and pos; an interior id is its own cell),
the record is a game-file actor with no user, it does not already stand in
that cell, and no other game hosts the cell where the record stands; then it
loads the record on demand and places it there (the grid, the position, the
heading), after which the normal path runs: its CreateActor with the hosted
word, the host's movement reports, puppets on the other screens. Validator
(wire-validate): 1 to 64 entries, each refrId under 0xff000000 and nonzero,
worldOrCell nonzero, every float finite. Appended to the contract (ADR-012);
the MsgType after HostRelease (49).

UpdateMovement (2), a validator change without a shape change (fork
m3-train-35, parity 8b43aa72 since 2026-10-22 23:48 PDT; docs/verbs/npc-puppet.md,
x-npc-death 20261023-054215): healthPercentage must lie in [0, 1], else Range. The
engine's deferred kill lets a host's actor sit below zero health (a script,
a fall) and the percentage read negative; the client clamps it at the source
(movementGet), the puppet apply never steps a figure or a puppet under one
percent (the server's death state is the only death), and the validator
refuses the rest as the untrusted input it is (rule 5). No field is new.

## Bridge and client FFI

Server: `wire-bridge` links into the existing C++ server through cxx and
corrosion (cargo inside the CMake build; the import is a relative path
because the workspace lives in the fork). The C++ side calls `poll()` and
receives `WireEvent { client, kind, payload }` where payload is an already
decoded, already validated struct; it calls `send()` with a struct. The old
`Networking.cpp`, `PacketParser`, and the RakNet dependency are deleted in
the same PR that lands the bridge; there is no dual-stack period on the
server.

Client: `wire-client-ffi` is a cdylib with a committed C header generated by
the cbindgen CLI. The SP plugin loads it, calls `connect`, `poll`, `send`,
`disconnect`, and receives `#[repr(C)]` views over decoded messages in
arrival order. Memory is owned by Rust and freed by Rust; the header says so
per function. The client's RakNet dependency goes in the same PR.

Migration phases:

1. M0: schema, codec, validate, transport, difftest, fuzz. Green on T2.
2. M1: bridge lands, C++ edge deleted, client cdylib lands, client RakNet
   deleted. `smoke-two-players` green on the new wire.
3. M1 onward: every new verb's handler is written in Rust behind the
   bridge; the bridge shrinks as handlers move across.

## Differential harness

The C++ core is the oracle for behavior we are not trying to change. In
M1 `difftest` compares two whole stacks run from the same world (ADR-019):

- legacy: the last RakNet server image (pinned by digest) and the C++
  fakeclient it ships;
- wire: the bridged server and the Rust fakeclient (wire-fakeclient), which
  keeps the C++ one's command line and event lines and runs the client DLL's
  own Rust code.

A session (YAML under `difftest/sessions/`) is a timed list of steps per
client, each a fakeclient script line: `move` (an UpdateMovement at the
spawn plus an offset) or `send` (SkyMP JSON as the client's networking
service sends it). Each stack runs one fakeclient per client, in declared
order and a fixed gap apart; the event lines are normalized (floats at f32
precision, received messages as a multiset, the timing-dependent relays
UpdateMovement, UpdateAnimation and UpdateAnimVariables as presence) and
diffed: login and spawn, exit code, what each client sent, what it received.
`DIFFTEST_LEGACY_FAKECLIENT` (or `DIFFTEST_FAKECLIENT`) with
`DIFFTEST_LEGACY_ADDR`, and `DIFFTEST_WIRE_FAKECLIENT` with
`DIFFTEST_WIRE_ADDR`, name the stacks (on sky-srv the legacy stack runs the
lab's settings without its .esl files, which it refuses by name; the server
under test numbers light plugins apart, so every full plugin keeps its index
on both); with one named it runs twice and
diffs against itself, which proves determinism only if the world is
restored between runs. The database dump joins the comparison when
`just test-proto` runs both servers side by side on sky-srv.

A difference the port means to make is declared in the session, not
normalized away: `divergences` lists a message one client receives a
different number of times on each stack, with the counts and the reason.
Declarations apply legacy against wire only and are reviewed like validator
changes; one that stops occurring as declared is itself a difference, so it
cannot outlive its cause. A message every client of every session shows
is declared once, in `difftest/divergences.yaml`, which the binary compiles
in (two entries: the game clock at login, ADR-021, and since train-29 the
player's globals at login, docs/verbs/player-globals.md); a change there
needs a fresh difftest-build before T2, where a sessions-only change runs
from the tree (`SESSIONS=`, lab/tools/test-proto.sh). The first, from T2 on 2026-10-02: in the smoke
session c2 sees c1's actor destroyed on the wire and not on RakNet, because
the C++ fakeclient exits without closing its connection (the legacy server
waits out RakNet's timeout) while the Rust fakeclient's close reaches the
wire server at once.

Corpus: lab captures. Wireshark's RakNet dissector stops at SkyMP's packet
id (0x86), so the RakNet framing is parsed directly (reliability header,
ordering, split reassembly; the capture holds both sides of docker's NAT)
and the packets are read into the schema by wire-legacy, which reads the
old binary format through the same serde types. Hand-written sessions cover
the paths the corpus never exercises.

A session names a form the server creates during the run (a drop, a placement) as
`"{{created:<baseId>}}"` instead of a fixed id (18:23 PDT 2026-10-29, fork m3-prop-physics
05184f99): the fakeclient keeps the latest form id each CreateActor named per base and
resolves the string when it sends (0 and an error event when none came), and the harness
resolves the same string in a declared divergence per stack, from that client's `created`
table in its normalized events, before matching. The first T2 of the prop-physics session had
assumed the generator's next id (0xff000004) and read the claim refused when earlier sessions
had allocated forms on the same server; the session names its dropped dagger by its base
(80254) now. The two stacks' generators differ by design, so `created` is never compared. A declared divergence may name per-field tolerances by dotted path (`within: {"data.health": 0.001}`) for the numbers the server takes from its own clock, which no replay reproduces to the digit (D66's counted gap: a4541cd0's T2 on a loaded host read 0.94792 where a quiet one read 0.94784, 2026-10-30); every other field matches exactly.

## Fuzzing

- `codec_decode`: arbitrary bytes into `wire_codec::decode`; must return
  `Ok` or `Err`; if `Ok`, encode must round-trip byte-for-byte.
- `validate`: `arbitrary`-derived messages into every validator; must not
  panic; property tests assert in-range accepts and out-of-range rejects.
- `json_recognize`: arbitrary bytes into wire-json's recognizer, the parser
  for what the core and the client hand the wire; an Ok must render and
  recognize back to the same message.
- `transport_ingest`: bytes into the renet server's packet ingestion after
  a scripted connect, including fragment sequences; must not panic and must
  not grow memory past the configured caps. This target exists because
  fragment reassembly is where RakNet-class bugs live.

All three run in GitLab CI on sky-ci (ADR-016): a bounded run on every push
that touches `skymp/skymp-wire/`, a longer run nightly; corpora are
committed.

## What this does not fix

Authority bugs (a validator that accepts a legal-looking lie) are covered by
the rungs and the T2 rejection tests, not by Rust. Panics are still denial
of service; the rules forbid them on the packet path and the fuzzers hunt
them. `unsafe` in the two FFI crates is reviewed by hand. The client's
remaining C++ (SKSE, SP, the engine) is unchanged; a malicious server versus
a player is fixed to the depth of the cdylib and no further.
